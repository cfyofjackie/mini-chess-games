# 国际象棋（Chess）设计规划

> 路线隶属 docs/PLATFORM.md。阶段一（同屏双人）= 2026-08-29 夜间子 Agent 并行开发；阶段二（AI）未排期。
> 实现模式遵循 src/games/gomoku/ 标杆。**全规则正确性是本项目的核心难点**，测试清单是验收核心。

## 一、规则规格（阶段一必须完整实现）

- **棋盘**：8×8，白在下先行。
- **基础走法**：王（一格）、后、车、象、马、兵（前进一格、起始位置可两格、斜吃）。
- **王车易位**：王与参与车均未动过（权利追踪）、之间无子、王不在被将军中、王经过与到达的格子均不受攻。
- **吃过路兵 (en passant)**：对方兵刚走两格的下一手内可用；机会即逝。
- **兵升变**：到底线必须升变；**升变自选（后/车/象/马）——本次实施，规格见第六节**。
- **将军 / 将死 / 逼和**：合法步 = 伪合法步 − 走后己王被攻的局面；无合法步时被将军=将死（负），不被将军=逼和（和）。
- **判和**：逼和、子力不足（K vs K、K+B/N vs K、K+B vs K+B 同色象）。
- **不做（本次实施范围外）**：50 回合规则、三次重复、记谱（PGN）。升变自选本次实施，见第五节。

## 二、阶段一交付（同屏双人）

- 引擎 `engine/chess.ts`：内部局面类型（棋盘 + 行棋方 + 易位权利 + en passant 目标格）、走法生成、`makeMove`、终局/和棋判定、undo（快照数组）。
- UI：Unicode 棋子（白 ♔♕♖♗♘♙ / 黑 ♚♛♜♝♞♟），8×8 明暗格（浅米/深灰绿类护眼配色），最后一手起止格高亮，被将军的王高亮警示。
- 交互：点击己方子 → 高亮合法落点（可吃子区分标记）→ 落子；chips：手数、轮次、将军提示；终局弹窗（将死/逼和/子力不足 + 胜方）；悔棋。
- 测试辅助：引擎导出一个小型局面构造函数（从简易描述设置棋子），方便搭测试局面。

## 三、测试清单（Vitest，全部须绿——这是验收核心）

1. 各兵种基础走法（含兵起始两格、斜吃无子不可走）。
2. 王车易位：长/短易位正例；各反例（权利已失、路径有子、王被将军、经过格受攻、目的地受攻）。
3. 吃过路兵：正常吃、机会窗口过期后不可吃。
4. 升变：到底线自动变后并参与后续走法。
5. 将死：学者将杀（Scholar's mate）等场景判定终局；被将军时应将步过滤。
6. 逼和：典型僵局局面判和。
7. 子力不足判和：三种组合。
8. 非法走子拒绝（走后己王送将等）；悔棋快照一致性。

## 四、阶段二路线（AI 对手）

材料 + 位置评估（PST）→ α-β + 迭代加深 + MVV/LVA 排序，深度 3-5；随后 quiescence。Worker 化同既有模式。

## 五、增量规格：升变自选（本次实施）

- **引擎**：`makeMove` 增加可选升变参数（后/车/象/马）。升变步**必须显式传入**升变子；未传时返回原状态（拒绝该步，保持纯函数"同引用拒绝"风格）。原"自动变后"逻辑与对应测试移除/改写。
- **UI**：兵到达升变线时，先弹出升变选择浮层（后/车/象/马四个按钮 + 取消），选择后完成走子；取消则回到选子前状态，可改走别的步。浮层复用全局 modal 样式风格。
- **测试清单（更新）**：
  1. 四种升变子各一例：升变后按新子的走法行动；
  2. 升变步未传升变参数 → 拒绝（同引用返回）；
  3. 升变步可选参数为非法值 → 拒绝；
  4. 原"自动变后"断言改写为"必须显式传参"。
- **范围说明**：本批次只做升变自选；AI 对手与 50 回合/三次重复仍留在后续阶段。

- 升变自选：本次实施后不再是缺口（见第五节）。
