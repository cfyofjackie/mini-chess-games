# 国际象棋（Chess）设计规划

> 路线隶属 docs/PLATFORM.md。阶段一（同屏双人）= 2026-08-29 夜间子 Agent 并行开发；阶段二（AI）未排期。
> 实现模式遵循 src/games/gomoku/ 标杆。**全规则正确性是本项目的核心难点**，测试清单是验收核心。

## 一、规则规格（阶段一必须完整实现）

- **棋盘**：8×8，白在下先行。
- **基础走法**：王（一格）、后、车、象、马、兵（前进一格、起始位置可两格、斜吃）。
- **王车易位**：王与参与车均未动过（权利追踪）、之间无子、王不在被将军中、王经过与到达的格子均不受攻。
- **吃过路兵 (en passant)**：对方兵刚走两格的下一手内可用；机会即逝。
- **兵升变**：到底线必须升变；**升变自选（后/车/象/马）——本次实施，规格见第六节**。
- **将军 / 将死 / 逼和**：合法步 = 伪合法步 − 走后己王被攻的局面；无合法步时被将军=将死（负），不被将军=逼和（和）。
- **判和**：逼和、子力不足（K vs K、K+B/N vs K、K+B vs K+B 同色象）。
- **不做（本次实施范围外）**：50 回合规则、三次重复、记谱（PGN）。升变自选本次实施，见第五节。

## 二、阶段一交付（同屏双人）

- 引擎 `engine/chess.ts`：内部局面类型（棋盘 + 行棋方 + 易位权利 + en passant 目标格）、走法生成、`makeMove`、终局/和棋判定、undo（快照数组）。
- UI：Unicode 棋子（白 ♔♕♖♗♘♙ / 黑 ♚♛♜♝♞♟），8×8 明暗格（浅米/深灰绿类护眼配色），最后一手起止格高亮，被将军的王高亮警示。
- 交互：点击己方子 → 高亮合法落点（可吃子区分标记）→ 落子；chips：手数、轮次、将军提示；终局弹窗（将死/逼和/子力不足 + 胜方）；悔棋。
- 测试辅助：引擎导出一个小型局面构造函数（从简易描述设置棋子），方便搭测试局面。

## 三、测试清单（Vitest，全部须绿——这是验收核心）

1. 各兵种基础走法（含兵起始两格、斜吃无子不可走）。
2. 王车易位：长/短易位正例；各反例（权利已失、路径有子、王被将军、经过格受攻、目的地受攻）。
3. 吃过路兵：正常吃、机会窗口过期后不可吃。
4. 升变：到底线自动变后并参与后续走法。
5. 将死：学者将杀（Scholar's mate）等场景判定终局；被将军时应将步过滤。
6. 逼和：典型僵局局面判和。
7. 子力不足判和：三种组合。
8. 非法走子拒绝（走后己王送将等）；悔棋快照一致性。

## 四、阶段二规格：AI 对手（本次实施）

- **分工**：人类执白先行，AI 执黑。
- **难度**：三档，工具栏内选择，默认中等：
  1. **简单**：深度 1（仅看己方一步，子料+PST 评估）——看不见对方回应，新手可胜。
  2. **中等**：α-β 深度 3 + MVV-LVA 走法排序 + 静态搜索（叶子只延伸吃子）。
  3. **困难**：迭代加深至深度 5（预算内）+ MVV-LVA + 杀手步/历史启发 + 静态搜索。
- **评估函数**：子料（兵100/马320/象330/车500/后900/王∞）+ 标准位置分表（PST，黑白镜像）；可加轻微机动性。保持确定性、无随机。
- **性能预算**：单步 ≤3s；**主预算用节点数**（保证确定性可复现），墙钟仅兜底；迭代加深保证任意时刻有当前最优步可返回。
- **性能优化许可**：搜索路径允许新增 make/unmake 式走子/撤销、增量化攻击检测等内部优化，**不得改变引擎既有公开 API 对外行为，既有 60 个测试必须保持全绿**。
- **不做**：置换表/Zobrist（列为后续优化选项）、重复局面与 50 回合判定（已知缺口：优势下 AI 理论上可能走出和棋重复）。
- **Worker**：`chess.ai.worker.ts` 薄封装（模式同 reversi/gomoku/chinese-checkers）；UI 难度选择 + AI 回合锁盘 + "AI 思考中" chip + undoToHuman。
- **测试清单（新增，引擎层直接测 ai.ts）**：
  1. AI 输出必为合法步（多场景 × 三档）；
  2. 一步将杀必找到（构造局面，三档全测）；
  3. 必胜残局（双车杀等）困难档在预算内找到将死路径；
  4. 不白送子：构造"送后"陷阱局面，中等/困难档不选送后着法；
  5. 等价换吃：目标子有保护时 AI 敢于换吃（静态搜索生效）；
  6. 优势避逼和：构造"随手棋即逼和"的胜势局面，困难档不选导致逼和的那步；
  7. 确定性：同一局面两次求解步与节点数完全一致；
  8. 预算合规：困难档最复杂中盘局面单步 ≤3s（墙钟）；
  9. 强度梯度：固定开局自对弈 hard vs medium 若干局并报告胜率（报告性，不作硬断言）。

## 五、增量规格：升变自选（本次实施）

- **引擎**：`makeMove` 增加可选升变参数（后/车/象/马）。升变步**必须显式传入**升变子；未传时返回原状态（拒绝该步，保持纯函数"同引用拒绝"风格）。原"自动变后"逻辑与对应测试移除/改写。
- **UI**：兵到达升变线时，先弹出升变选择浮层（后/车/象/马四个按钮 + 取消），选择后完成走子；取消则回到选子前状态，可改走别的步。浮层复用全局 modal 样式风格。
- **测试清单（更新）**：
  1. 四种升变子各一例：升变后按新子的走法行动；
  2. 升变步未传升变参数 → 拒绝（同引用返回）；
  3. 升变步可选参数为非法值 → 拒绝；
  4. 原"自动变后"断言改写为"必须显式传参"。
- **范围说明**：本批次只做升变自选；AI 对手与 50 回合/三次重复仍留在后续阶段。

## 六、已知取舍（2026-08-30 更新）

- 50 回合规则、三次重复判和：仍为已知缺口（后续 AI 阶段一并处理或单独补）。
- PGN/FEN 互导：不做（内部结构保持简单）。
- 升变自选：本次实施后不再是缺口（见第五节）。

## 七、增量规格：走子可读性与棋子辨识（UX，本次实施）

> 来源：玩家实测反馈——AI 应手太快看不清发生了什么；黑白棋子区分不明显。五项改动，全部限国象目录。

1. **A1 AI 落子停顿**：Worker 回复到达后不立即落子，固定延迟 **600ms** 再应用 AI 着法。延迟期内"AI 思考中"chip 的处理实现自选（保留或先撤掉均可），但玩家必须能感知"AI 想好了，正要落子"的节奏。重开/换难度/悔棋时必须取消挂起的延迟（不落地过期着法）。
2. **A2 落子滑动动画**：AI 落子（及人类落子，尽量共用）的棋子从起点格**滑动**到终点格，时长约 250ms、缓动收尾；实现参考 src/games/peg-solitaire 的 `--dx/--dy` 滑入模式（Board 按 lastMove 加动画类）。
3. **A3 被吃棋子淡出**：被吃的棋子在原格**缩小 + 淡出**约 300ms 后消失（渲染"幽灵"元素，以着法序号作 key 触发动画，同独立钻石被吃子模式）。
4. **A5 上一手文字提示**：状态条新增 chip 显示最近一手，格式：`你：白后 d1×h5`（吃子用 ×）或 `AI：黑兵 e7-e5`。人类与 AI 的着法都显示，随新着法替换。文案由**纯函数**生成（棋子中文名 + 代数坐标），放 `ui/moveText.ts` 并配套 `ui/moveText.test.ts`：非吃子 / 吃子 / 升变（含升变子名）各一例。
5. **B1 棋子上色**：白方棋子渲染为**实心白（近 #fff）+ 深色描边**，黑方棋子**实心近黑（#1c1c26 类）+ 浅色描边**（-webkit-text-stroke 或 text-shadow 实现）；明暗两种格子上都必须一眼可辨。

### 验收标准

- AI 应手时序：思考 chip → 停顿 → 滑动动画 → 被吃子淡出 → 上一手 chip 更新，全程玩家可跟随。
- 白子/黑子在浅格与深格上截图肉眼可辨（集成阶段人工确认）。
- 既有 70 个测试保持全绿 + moveText 新增测试全绿；不触碰其他游戏与共享文件。

## 八、增量规格：复盘报告 v1（本次实施，纯前端、零服务器）

> 玩家需求：下完想知道自己输在哪。原理：着法记录（history）就在引擎状态里，分析 = 用现有 AI 搜索逐局面重评，全部在浏览器本地完成。

### 范围（v1）

1. **入口**：终局弹窗与游戏页工具栏新增"复盘本局"按钮（对局进行中也可进入，分析截至当前局面）。
2. **分析器**（纯函数，`engine/analysis.ts` + `analysis.test.ts`）：
   - `analyzeGame(initialState, moves, options) → Report`：按 history 重放，逐局面用 AI 搜索（固定参数：中等深度、小节点预算，保证速度）求"最佳着法 + 评估分"；玩家每手评分 = 该手行棋方视角的评估差。
   - 分级：🟢 最佳（≈引擎首选或 Δ≈0）/ ⚪ 好棋（小损）/ 🟡 失误（中损）/ 🔴 大错（大损：丢子级/漏杀）。阈值实现自定，但须可测试。
   - Report 数据结构含：每手的评级、评估分（转白方视角曲线）、最佳着法、一句话原因（规则化文案：丢子/送杀/错过绝杀/换子亏/平稳）。
3. **报告 UI**（`ui/Report.tsx`，游戏页内切换视图）：
   - 着法时间线（红白分栏或列表），按评级着色；
   - 评估曲线（内联 SVG 折线，白方视角）；
   - 点击任一手 → 棋盘跳转到该局面（复用 Board 渲染指定局面），并显示该手评级与原因；
   - 复盘在 Worker 里跑（扩展 chess.ai.worker 协议：`analyze` 请求 + 每手进度回报），界面有进度条（x/N）。
4. **本地保存**：报告完成后存 localStorage（key 前缀 `chess-review-`，保留最近 10 局）；提供历史列表可重看。URL 分享编码不做（记录为后续）。

### 测试清单（新增，引擎层直接测 analysis.ts）

1. 一步杀对局：报告把制胜手标为 🟢 最佳，且曲线在终局达到将死分；
2. 送后陷阱对局：送后那手被标 🔴 大错，原因含"丢后"；
3. 平稳开局序列（意大利开局前若干步）：无 🔴，多为 🟢/⚪；
4. Report 曲线数据点数 = 手数 + 1；
5. 被吃子原因文案正确（丢马/丢兵等）。

### 明确不做（v1）

- URL 分享编码、跨设备同步、云端更深分析；
- 多游戏复用（先在国象试点，跑通后推广）；
- 逐手"教练重试"交互（属教练模式第二层，另行排期）。
