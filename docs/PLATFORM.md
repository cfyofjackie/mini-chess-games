> 关联文档：[独立钻石设计](../DESIGN.md) · [README](../README.md)

## 一、背景与决策记录

独立钻石 v0.1 已交付（引擎/求解器/UI 分层，测试、构建、浏览器实测通过）。下一阶段目标：**同一网页内提供多种棋类**——打开是游戏大厅，点选进入五子棋、跳棋、独立钻石等，共享一套视觉与工程结构。

| 决策点 | 结论 | 理由 |
|--------|------|------|
| 组织方式 | 单仓库单应用，注册表模块化 | 一次部署全站生效；新棋 = 新文件夹 + 一行注册，互不干扰 |
| 路由 | 自实现 hash 路由（`#/gomoku`），不引 react-router | 约 20 行代码；hash 路由对 GitHub Pages 子路径部署零配置，刷新/分享链接均可恢复 |
| 加载 | `React.lazy` 动态导入，按棋分包 | Vite 自动切 chunk：大厅首屏只有菜单，点进哪局才下载哪局的代码 |
| 视觉 | 公共组件抽到 `shared/`，风格 token 共用 | 大厅里切换游戏是"一个产品"的观感，而非 demo 拼盘 |
| 流程 | 每种棋独立规划（设计 + 里程碑），沿用既有纪律 | 引擎先行 + 纯函数 + 单元测试 + UI 只做壳——独立钻石一次做对的方法论直接复用 |

## 二、目标目录结构

```
src/
├── games/
│   ├── registry.ts          # 游戏清单：id、名称、图标、懒加载入口
│   ├── peg-solitaire/       # 现有独立钻石整体迁入（engine/ solver/ ui/）
│   ├── gomoku/              # 五子棋：engine/ + ui/ + ai worker
│   └── checkers/            # 跳棋（变体待定）
├── shared/                  # 公共组件：按钮、弹窗、Toast、状态条、页面骨架
├── styles.css               # 全局风格 token（现文件迁移/拆分）
└── App.tsx                  # 大厅 + hash 路由分发
docs/
├── PLATFORM.md              # 本文
└── games/<id>.md            # 以后每种棋各自的设计沉淀
```

## 三、核心机制

### 3.1 游戏注册表

每个游戏模块向注册表登记一条元信息，大厅据此渲染列表：

```ts
// games/registry.ts
export interface GameModule {
  id: string;                       // 路由标识，如 'gomoku'
  name: string;                     // 大厅显示名，如 '五子棋'
  description: string;              // 一句话简介
  component: LazyExoticComponent;   // 懒加载的游戏入口组件
}

export const GAMES: GameModule[] = [
  { id: 'peg-solitaire', name: '独立钻石', description: '跳过邻子，只留一颗', component: lazy(() => import('./peg-solitaire/ui')) },
  // 新棋在这里加一行
];
```

### 3.2 大厅与路由

`App.tsx` 监听 `hashchange`，按 `#/gameId` 匹配注册表：未匹配或无 hash → 渲染大厅列表；匹配 → `<Suspense>` 包裹渲染对应游戏。URL 可分享、刷新后回到同一局棋的入口。

### 3.3 懒加载分包

每种棋一个 chunk，由 Vite 在构建时自动完成。部署方式完全不变：仍是一个静态目录推 GitHub Pages，分包只影响浏览器按需取哪些文件。

### 3.4 公共组件层

从现有 `src/ui` 抽取 `Btn / Modal / Toast / Chip / GameShell`（页面骨架）到 `shared/`，各棋 UI 只写棋盘与玩法特有的部分。颜色、圆角、阴影 token 沿用现 styles.css。

## 四、接入一款新棋的标准流程

1. `games/<id>/engine/`：纯函数棋局引擎 + Vitest 单元测试（先行，不碰 DOM）
2. `games/<id>/ui/`：useReducer 状态机 + 组件，状态全部来自引擎
3. 可选 `games/<id>/ai.worker.ts`：AI 或求解器放 Worker，不卡界面
4. `registry.ts` 加一行 → 自动出现在大厅
5. 设计沉淀到 `docs/games/<id>.md`

## 五、新棋规划检查单

规划每种棋时先回答四个问题（独立钻石的答案依次是：单人解谜 / 选子-跳 / 无 / 无和棋）：

1. **对手问题**：单人解谜、同屏双人，还是需要 AI 对手？AI 用极小极大 + α-β 剪枝 + 启发排序，放 Worker（五子棋到"业余中等水平"现实可行，求解器经验复用）。
2. **交互模型**：选子→跳（钻石）、点空位落子（五子棋）、拖拽/连跳（跳棋）——均属"点击棋盘"一族，可共享交互基建。
3. **变体歧义**：同名异种先定清楚（如"跳棋"＝中国跳棋六角星多人，还是国际跳棋 8×8 吃子，两者规模差数倍）。
4. **终局与和棋**：胜负判定规则、和棋条件、是否需要禁手（如五子棋三三禁手可选）。
